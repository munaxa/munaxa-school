## Usage rules
Use inside approved patterns after permission filtering. Pass localized values and stable states. Keep fetching, authorization, mutation, and transitions outside presentation components.

## Do
- Reuse shared foundations.
- Provide explicit state, scope, and accessible labels.
- Compose loading, empty, denied, error, approval, and read-only states.

## Don’t
- Copy markup or add one-off status colors.
- Hide unauthorized data only in the browser.
- Use cards without workflow purpose.

## Accessibility
Text accompanies status. Controls work by keyboard, have names, preserve focus, and do not rely on hover, color, sound, or motion.

## RTL
Use logical flow and real Arabic. Isolate amounts, phone numbers, IDs, and mixed-direction strings.

## Dark mode
Use semantic tokens only. No neon, glow, glassmorphism, or luminous statuses.

## Examples
Complete compositions under domain-components/examples use only approved APIs.
