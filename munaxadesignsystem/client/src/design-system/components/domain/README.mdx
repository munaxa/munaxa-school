# Domain components

## Overview

Domain components encode Munaxa school concepts above generic UI primitives. The complete per-component catalog, props, variants, and states are documented in the repository root DOMAIN_COMPONENTS.md.

## Usage

Import from @/design-system/components/domain after server-side permission filtering. Keep data loading, authorization, formatting, and workflow transitions outside presentation components.

## Examples

Use StudentCard in CRUD results, AttendanceRiskIndicator in student profiles, InvoiceCard in finance workflows, BusCard in transport operations, NotificationCard in the durable inbox, and ReportFilterBar above report results.

## Best practices

Prefer these APIs over copied card markup. Pass localized display values and stable domain statuses. Compose skeleton, empty, error, denied, and approval states at the pattern level.

## Accessibility notes

Statuses include text and semantic tone. Timelines use ordered lists. Consumers label actions and retain correct heading order.

## RTL notes

Components use logical flow. Isolate currency, identifiers, telephone numbers, and mixed-direction strings when needed.

## Dark mode

Semantic tokens preserve restrained enterprise contrast. Neon, glow, glassmorphism, and color-only hierarchy are prohibited.
